# 2BL 角色／日期／狀態矩陣

## 角色權限

| 角色 | 正式範圍 | 可操作 | 不可操作 | 本次唯讀現況 |
|---|---|---|---|---|
| 平台最高總管 | 全平台 | 全部營運模組、租戶設定、權限與必要刪除 | 不得繞過正式登入或資料隔離 | 2 個啟用帳號 |
| 租戶擁有者 | `tuibile` | 租戶營運、設定、管理者、會員、財務 | 不得進入平台總管功能；不可刪除正式資料 | 角色規格已存在，目前未盤出啟用帳號 |
| 指定系列管理者 | 被指定活動系列與其場次 | 報名、場次、排位、現場、通知與系列財務 | 不可跨系列、不可刪除、不可管理租戶或管理者 | 3 個啟用帳號 |
| 單場管理者 | 被指定場次 | 報名、場次、排位、現場與通知 | 不可看整體財務、會員與租戶設定 | 角色規格已存在，目前未盤出啟用帳號 |
| 財務管理者 | 授權財務範圍 | 財務檢視與核對 | 不可操作報名、場次、排位、現場與帳號 | 角色規格已存在，目前未盤出啟用帳號 |
| 現場工讀生 | 通行碼指定場次 | 報到、撤場及現場狀態 | 不可進入管理後台、財務、會員或其他場次 | 使用場次通行碼，不建立平台權限 |
| 一般會員 | 自己的會員與報名 | 報名、付款回報、查看紀錄、取消與退款申請 | 不可看其他會員或管理資料 | 由會員流程驗證 |
| 公開訪客 | 公開活動與持有分享網址的內容 | 查看開放場次、公開資訊、唯讀財報分享 | 不可取得管理功能與內部來源 | 由公開入口驗證 |

## 固定權限驗收

每次涉及登入、角色、權限、路由、共用 API 或資料範圍的修改，部署前後都必須驗證：

1. 登入與重新登入。
2. 重新整理。
3. 站內返回。
4. 直接開啟網址。
5. 合法功能存取。
6. 跨角色與跨系列阻擋。
7. API 與資料範圍隔離。

任一合法角色進不去，或任一角色發生越權，立即判定失敗。

## 日期矩陣

| 功能 | 單日 | 跨日 | 正式判斷來源 | 邊界規則 |
|---|---|---|---|---|
| 報名開放 | 使用該場活動日 | 使用最早活動日計算階段 | 場次報名排程 | 每段完整填寫且總開關開啟才生效 |
| 報名日期選擇 | 當日 | 依報名選擇的日期 | 報名資料 | 不得自動把未選日期視為參加 |
| 攤位數 | 報名攤位數 | 同一品牌各日實際使用量分開；報名攤位總數不得和每日使用量混用 | 報名與逐日排位資料 | 品牌數、租用攤位數、每日使用量是三種不同統計 |
| 排位 | 當日位置 | 每日位置可相同或不同 | 逐日排位資料 | 畫面切換日期後不得跳回其他日期或其他攤商 |
| 報到 | 當日一次 | 每日分開 | 逐日現場紀錄 | 不得用全場已報到覆蓋每日狀態 |
| 撤場 | 當日一次 | 每日分開 | 逐日現場紀錄 | 未完成撤場不得進入當日完成狀態 |
| 押金 | 最後參加日 | 兩日只收／退一次正式押金 | 退款交易與逐日現場紀錄 | 非最後參加日顯示不適用；撤銷只回復狀態與金額，不得建立第二筆退款 |
| 設備 | 當日數量 | 依日期分開統計 | 報名設備與場次日期設定 | 上限、費用與實際配發不得跨日重複計算 |
| 財報 | 場次正式收款 | 同一報名只依正式交易計算 | 付款、退款與支出帳本 | 押金不列營業收入；退款不得重複扣除 |
| 通知 | 場次時程 | 使用最早活動日及各日營運狀態 | 場次與通知資料 | 同一事件需保留寄送與已讀紀錄 |

## 報名與付款狀態

| 流程 | 可進入狀態 | 可離開狀態 | 必須保留的證據 |
|---|---|---|---|
| 報名送出 | 待審核或依場次規則錄取 | 審核、取消 | 報名時間、場次、日期、設備與金額快照 |
| 審核 | 待審核 | 已錄取、不錄取、備取 | 操作者、時間與狀態變更 |
| 付款回報 | 未繳費 | 待確認 | 付款方式、回報時間與憑證引用 |
| 確認收款 | 待確認或人工確認 | 已繳費 | 正式付款紀錄，不只修改畫面文字 |
| 取消 | 未繳費、待確認、已繳費 | 已取消 | 取消原因、退款需求與原始狀態 |
| 退款 | 已繳費或依法成立的退款 | 已退費 | 唯一退款交易、金額、操作者與時間 |
| 押金撤銷 | 誤標已退但實際未退 | 未退押金 | 撤銷原因；不得保留虛假退款交易 |
| 活動金 | 正式產生的可用額度 | 使用或人工作廢 | 追加式帳本，不得直接覆寫餘額 |

## 場次狀態

目前正式場次：報名中 16、封存 7、已關閉 1、關閉 1。`已關閉` 與 `關閉` 為兩個現存值，未定義安全轉換前不得自行統一。
